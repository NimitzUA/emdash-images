# Orca setup for this repository

How this repository is wired for the supervised Orca workflow. The workflow files are generated by
orca-setup from `.orca-setup.json`; the few settings that live in Orca, Codex and git config are
listed here so they can be entered by hand.

## Roles

- **Architect** («Role: Architect») plans with the user: plans in `docs/plans`, ADRs in
  `docs/adr`, templates in `docs/templates`, open work in `docs/ROADMAP.md`. It writes no feature
  code.
- **Architect run** («Role: Architect run») runs one approved plan per fresh session through the
  `run-plan` skill: one worktree and branch `task/<NNN-slug>` per plan, a Codex executor per task,
  a fresh Claude reviewer per task, the plan gates, the merge and a check in a fresh worktree of
  `main`.
- **Executor** is plain `codex`: the trusted `.codex/config.toml` gives the model, effort and the
  `emdashimages` permission profile.

Every task proves itself with `npm test` (`scripts/orca/check.sh`); the plan gates run the
dependency install (`npm ci`) and `npm test`.

## 1. Orca project settings (manual)

Settings → Projects → emdash-images:

- **Worktree Location:** `.worktrees` (git-ignored).
- **Base ref:** local `main`, not `origin/main`.
- **Setup:** from `orca.yaml`, run by default, «wait for setup before starting the agent» on.
  Setup sets `core.hooksPath` and installs the dependencies with `npm ci`.

## 2. Codex trust (manual)

Codex applies `.codex/config.toml` only to a trusted project. `~/.codex/config.toml` needs:

```toml
[projects."/Users/serhii/Developer/emdash-images"]
trust_level = "trusted"
```

Worktrees under `.worktrees/` inherit it.

## 3. Git hooks in the main checkout (manual, once)

```bash
git -C /Users/serhii/Developer/emdash-images config core.hooksPath .githooks
```

New worktrees get it from `orca.yaml`.

## 4. Quick commands

Stored in Orca's settings, not here. The current set:


## 5. Checks

```bash

python3 ~/.claude/skills/orca-setup/scripts/doctor.py /Users/serhii/Developer/emdash-images
```

## 6. Notes

- The service tests fall back to `.dev/image-cache` for their image cache; `.dev/` is git-ignored.
  The npm cache of a worktree lives in `.npm-cache/`, also git-ignored.
- Pushes and release tags stay with the owner: agents are denied `git push` and `git tag`, and the
  release process is still open (`docs/ROADMAP.md`).
- Never commit `.claude/**` or `.codex/**` to `main` while a plan worktree exists: the next rebase
  onto it stops in the Claude sandbox.
